## Goal

重构旁白功能使其更合理地存在于角色扮演系统中：
1. **旁白身份回复**：AI 回复以旁白（叙述者）身份输出，而非角色口吻
2. **记忆可控**：旁白消息默认不计入记忆，生成后可通过长按菜单手动标记「加入记忆」
3. **可选生成**：旁白模式支持两种操作——仅插入旁白描述（不触发AI）和插入旁白+触发AI回复
4. **指令注入**：自动注入旁白专用 system 指令，让 AI 以旁白视角描述场景/角色状态/内心想法
5. **信息查看**：旁白指令引导 AI 查看 Lorebook 和记忆摘要来回答世界背景/角色想法

## Scope / Non-goals

**Scope（包含）：**
- ChatService 层：修改 `narratorMessage()` 的 AI 回复消息 `senderType`；新增 `sendNarratorOnly()` 方法；`doStream()` 注入旁白指令
- 数据模型层：`ChatMessage` 新增 `includeInMemory` 字段；数据库 v37 迁移新增列
- 记忆层：`MemoryService.formatMessages()` 过滤 `includeInMemory === false` 的消息
- UI 层：旁白模式下两个发送按钮；ChatMessageActionSheet 支持旁白消息操作和「加入记忆」
- PromptBuilder 层：旁白回复消息也需要标记为 `NarratorInstruction` source

**Non-goals（不包含）：**
- 不修改 Lorebook 系统本身（旁白通过注入指令引导 AI 利用现有 Lorebook）
- 不修改记忆摘要的结构（只在 formatMessages 层过滤）
- 不修改 ChatRole 枚举（旁白回复仍用 `ChatRole.Assistant`，仅 `senderType='narrator'`）
- 不修改 PromptBuilder 的 segment position 体系
- 不实现多人聊天中的旁白功能（仅单角色）

## Current State And Constraints

### 当前旁白功能的问题

| 问题 | 描述 |
|---|---|
| AI 回复是角色身份 | AI 回复消息 `senderType='character'`，以角色口吻回复而非旁白叙述 |
| 旁白必触发AI | 没有只插入旁白描述不触发AI的选项 |
| 旁白计入记忆 | 所有旁白消息自动进入记忆摘要，无法控制 |
| 无旁白专用指令 | 没有注入告诉AI如何以旁白视角回复的指令 |
| 操作菜单空白 | 长按旁白消息无操作项（System 角色不在 if 分支中） |
| ContextBudget 缺失 | `NarratorInstruction` 不在 `orderedSources` 中，预算显示遗漏 |

### 现有旁白消息数据流

```
用户输入旁白 → sendNarrator() → narratorMessage()
  → 创建消息1: role=System, senderType='narrator' (旁白输入)
  → 创建消息2: role=Assistant, senderType='character' (AI回复) ← 问题: 应为 narrator
  → doStream() → 无特殊旁白指令注入 ← 问题: AI 不知道以旁白身份回复
  → MemoryService.formatMessages() → 无过滤 ← 问题: 旁白内容无条件进入记忆
```

### ArkTS 约束
- `ChatMessage` 是 interface，新增字段需同步 `createChatMessage()` 和 `mergeChatMessage()`
- `MessageSenderType = 'user' | 'character' | 'narrator'` 已包含 `'narrator'`，无需扩展
- 数据库迁移需要新增 v37 step
- `ChatMessageActionSheet` 的 `MessageAction` 类型需要扩展新的 action
- `ChatMessageRenderState` 需新增 `includeInMemory` 字段以驱动 UI 状态

### 6. MemoryService — 过滤不计入记忆的消息

**[MemoryService.ets](entry/src/main/ets/services/MemoryService.ets)** `formatMessages()` 方法：

```typescript
private formatMessages(messages: ChatMessage[]): string {
  const parts: string[] = [];
  for (let i = 0; i < messages.length; i++) {
    const msg: ChatMessage = messages[i];
    // 跳过明确标记不计入记忆的消息
    if (msg.includeInMemory === false) {
      continue;
    }
    let role: string;
    if (msg.senderType === 'narrator') {
      role = '旁白';
    } else if (msg.role === ChatRole.User) {
      role = '用户';
    } else if (msg.role === ChatRole.Assistant) {
      role = '角色';
    } else {
      role = '系统';
    }
    parts.push(role + ': ' + msg.content);
  }
  return parts.join('\n');
}
```

同样，`regenerateSummary()` 和 `doGenerateChapter()` 中收集消息时也应过滤 `includeInMemory === false` 的消息。

### 8. ChatViewModel — 新增 sendNarratorOnly()

**[ChatViewModel.ets](entry/src/main/ets/viewmodels/ChatViewModel.ets)**：

```typescript
async sendNarratorOnly(): Promise<void> {
  if (this.disposed || !this.canSend()) {
    return;
  }
  const content: string = this.inputText.trim();
  if (content.length === 0) {
    return;
  }
  this.errorMessage = '';
  this.statusMessage = '';
  this.inputText = '';
  const callbacks: ChatServiceCallbacks = this.createCallbacks();
  try {
    await this.chatService.narratorMessageOnly(content, callbacks);
  } catch (e) {
    this.errorMessage = this.toUserError(String(e));
    Logger.error(LOG_TAG, 'sendNarratorOnly failed: ' + String(e));
  }
}
```

### 12. ChatService — 新增 markMessageIncludeInMemory()

```typescript
async markMessageIncludeInMemory(messageId: string, include: boolean): Promise<void> {
  if (this.disposed) {
    return;
  }
  const idx: number = this.findMessageIndexById(messageId);
  if (idx < 0) {
    return;
  }
  const msg: ChatMessage = this.messages[idx];
  const updated: ChatMessage = mergeChatMessage(msg, { includeInMemory: include });
  this.messages[idx] = updated;
  if (this.persistenceService !== null && this.currentChatId !== undefined) {
    await this.persistenceService.updateMessage(messageId, updated);
  }
}
```

## Risks And Compatibility

| 风险 | 应对 |
|---|---|
| v37 迁移影响 | `ALTER TABLE ADD COLUMN` 是安全的增量操作，DEFAULT 1 保证旧消息兼容（旧消息都计入记忆，行为不变） |
| 旁白回复改 senderType | 修改后旁白回复消息以 narratorBubble 渲染（居中灰色），而非 assistantBubble。这是预期行为变化。旧数据库中已有的旁白回复消息仍为 senderType='character'，不会受影响 |
| 记忆过滤遗漏 | 需要确保 `regenerateSummary()` 和 `doGenerateChapter()` 中的消息收集也过滤 includeInMemory=false |
| AI 可能不遵循旁白指令 | 模型对 system 指令的遵循程度不一。旁白指令要尽量明确简洁 |
| ChatRole.Assistant + senderType='narrator' 组合 | 这是新组合，需确认 PromptBuilder、HistoryTrimmer 等所有按 role 判断的地方不会出问题。当前 PromptBuilder 按 senderType 判断 source，senderType='narrator' 优先于 role，所以安全 |

## Rollback

1. 数据库：v37 的 `include_in_memory` 列无法自动回退（SQLite 不支持 DROP COLUMN），但列存在不影响功能（DEFAULT 1 使旧行为不变）
2. 代码回退：git revert 所有改动即可
3. 最坏情况下：旁白功能恢复为 AI 以角色身份回复、自动计入记忆，用户体验降级但不会崩溃
